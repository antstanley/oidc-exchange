## Steps

- [x] Declare the claim-name cap as a named constant (e.g. `MAX_EMAIL_VERIFIED_CLAIM_LEN` = 64), counted in Unicode code points per the change spec's Decision — validate with `chars().count()`, not byte length.
- [x] Lift in `provider_config_to_oidc`: `email_verified_claim` via `as_str` → `EmailVerification::Claim(name)`, with a `ConfigError` naming the provider for a non-string TOML value, an empty string, or a name over the cap; `trust_email_verified` via `as_bool` → `TrustEmail` on `true`, `Standard` on an explicit `false` (identical to the key being absent), and a `ConfigError` — never a coercion — for a set-but-non-boolean value; both keys set on one block → `ConfigError`; neither key → `Standard`.
- [x] Emit one structured `tracing::warn!` per provider whose resolved mode is not `Standard`, at registry build in `build_single_provider`, with fields for the provider id and the mode (and the mapped claim name for `Claim`), following the structured-warning precedent at `bootstrap.rs:566-590` — structured for unit-testability: either behind a pure helper (e.g. `fn email_verification_warning(mode) -> Option<…>`) or emitted immediately after the synchronous `provider_config_to_oidc` call, before the async `from_config().await`.
- [x] Add the warning test: assert exactly one warning for a `Claim` fixture and one for a `TrustEmail` fixture, and zero warnings for a `Standard` fixture, captured via `tracing::subscriber::with_default` with a capturing writer (or `install_span_capture` from the test-utils crate) in the `bootstrap.rs` `#[cfg(test)]` module — or as an integration test on the existing wiremock-discovery pattern.
- [x] Add tests beside `provider_config_to_oidc_tests`: each key lifts to its variant; explicit `trust_email_verified = false` → `Standard`; neither key → `Standard`; both keys set → `ConfigError`; non-boolean `trust_email_verified` → `ConfigError`; non-string, empty, and over-cap `email_verified_claim` → `ConfigError`; an exactly-64-code-point name is accepted (the `exactly_at_the_cap_is_accepted` boundary pattern), including a multi-byte name whose byte length exceeds 64 — pinning the code-point count.
- [x] Add the resolve-level Entra boot test through `resolve_config_toml` (the `:1923` fixture pattern): `adapter = "oidc"`, a v2.0 `login.microsoftonline.com` issuer, `client_id`, `scopes = ["openid", "email", "profile"]`, `email_verified_claim = "xms_edov"` — resolution succeeds.
