## Work

- Publish an internal API schema covering the paths, `UserStatus`, `UserPage`, `OperatorPrincipal`-relevant credential contract, cursor query/response, and 429 semantics needed by the console.
- Add deterministic build-time generation and freshness checking; replace the handwritten `api()` and handwritten types rather than layering generated fragments over them.
- Generate percent-encoded path parameters and canonical snake_case enums by construction; update list UI/loaders to use cursor/`next_cursor` completion rather than offset or short-page assumptions.
- Select credentials server-side in the documented preference order: token, client certificate/key, then compatibility secret. Keep them out of browser code and preserve default `INTERNAL_API_URL` admin port.

## Definition of done

- [x] A clean build regenerates client/types from the checked-in schema and a stale generated artifact fails a reproducible freshness check. (`pnpm build` runs `pnpm generate` before `vite build`; `scripts/generate-client.mjs --check` (`pnpm generate:check`) re-generates in memory and exits 1 with "generated client is stale" on any byte difference. Output is a pure function of the schema — no timestamps, no environment reads, sorted operations/imports — verified byte-identical across consecutive runs, and `.oxfmtignore` (passed via oxfmt's `--ignore-path`, which oxfmt does not auto-discover) keeps the formatter from reflowing the artifacts.)
- [x] Generated user paths encode a segment; generated status types accept only service wire values; tests exercise both properties without hand-written workaround code. (The generator wraps every `{param}` in exactly one `encodeURIComponent` at generation time; `api.test.ts` replays correction #41's hostile ids (`x%2f..%2fstats`, `%2e%2e%2fstats`) against the generated client — no handwritten `api()` remains. `types.ts` renders `UserStatus` as the schema's literal union `"active" | "suspended" | "deleted"` and `types.test.ts` pins those exact runtime values.)
- [x] Cursor pagination follows non-null `next_cursor`, including a short page with a next cursor; it no longer sends `offset`. (Generated `listUsers` follows `next_cursor` to null under a `PAGER_MAX_PAGES = 1000` bound; `pagination.test.ts` proves cross-page aggregation, short-page continuation, `cursor`/`limit` query composition, and the absence of any `offset`. The users loader navigates by `next_cursor` via a URL cursor stack; the `page`/`offset` parameters are gone.)
- [x] Browser-facing output contains no internal credential, while server-side env selection observes the documented precedence and handles missing credentials safely. (`api.ts` imports `$env/dynamic/private`, so reaching it from browser code fails the build; only `+page.server.ts` loaders import it. `resolveOperatorCredential` implements the schema's `x-credentials.preference` — token, then complete certificate/key pair over mTLS via `tls-transport.ts`, then shared secret — and `credentials.test.ts` covers the full matrix: precedence order, half-configured pairs erroring instead of downgrading, and fail-closed when nothing is configured. Credential values are never logged.)
- [x] `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, and relevant `pnpm test` pass; Rust/schema checks needed by the generator also pass; unrelated failures are recorded but not fixed. (All four admin-ui gates green: format/lint clean, svelte-check 0 errors, vitest 19 passed across api/types/credentials/pagination; `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and full `cargo nextest run --workspace` green at 463 passed / 27 skipped.
